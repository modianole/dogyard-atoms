
מושלם — הנה תכנית ביצוע ממוקדת כדי לסגור את זה סופית באתר החי (לא רק ב-Preview), כולל בדיקת E2E מלאה כמו שביקשת.

### מה כבר בדקתי לעומק
1. באתר החי הנתיב `/auth` כן נטען תקין (הדף קיים ונגיש).
2. כפתור "כניסה" מוצג באתר החי.
3. זיהיתי לוג של `refresh_token_not_found` — זה סימן קלאסי ל-session ישן/פגום בדפדפן שיכול לגרום להתנהגות "לחיצה לא עושה כלום" או קפיצה חזרה.
4. בדיקת הרשמה בפועל הראתה שהמערכת דורשת אימות אימייל (נוצר משתמש חדש לא מאומת), ולכן אי אפשר להשלים “פתיחת משתמש וחזרה מחובר” בלי אימייל נגיש לאימות.

### תכנית תיקון (קוד + קשיחות)
1. **הקשחת אתחול auth** (`src/hooks/useAuth.ts`)
   - להוסיף ולידציה של session מול השרת באתחול.
   - אם session לא תקין/refresh token שבור: ניקוי session מקומי בצורה יזומה ועדכון state נקי.
   - למנוע מצב transient שבו האפליקציה חושבת בטעות שהמשתמש מחובר.

2. **הקשחת דף התחברות** (`src/pages/Auth.tsx`)
   - לשנות redirect אוטומטי ל־`/` רק אחרי ש-auth bootstrap הסתיים בוודאות.
   - לא לבצע redirect על user “רגעי” לפני ולידציה.
   - להציג הודעת שגיאה ברורה אם יש session שבור ולנקות אותו במקום.

3. **קשיחות ניווט בכפתור כניסה** (`src/components/Navbar.tsx`)
   - להשאיר ניווט קשיח ל-`/auth` (לינק ישיר), עם fallback ניווט נוסף במקרה קצה.
   - לוודא סגירת תפריט מובייל ללא ביטול ניווט.

4. **Self-heal ללקוחות עם cache/Service Worker ישן** (`src/main.tsx` + הגדרת PWA)
   - להוסיף מנגנון version check חד-פעמי:
     - זיהוי build ישן.
     - ניקוי cache/service-worker legacy פעם אחת.
     - רענון אוטומטי מבוקר.
   - המטרה: משתמשים “תקועים” יקבלו אוטומטית גרסה נקייה בלי להסתמך על Ctrl+F5.

### בדיקת קבלה מחייבת (E2E באתר החי)
1. לפתוח את האתר החי בדפדפן נקי.
2. ללחוץ "כניסה" מהמסך הראשי → חובה להגיע ל-`/auth`.
3. **פתיחת משתמש חדש + התחברות בפועל + חזרה לדף הבית מחובר**:
   - אם אימות אימייל נשאר פעיל: לבצע אימות דרך תיבת דוא"ל ואז להתחבר.
   - אם תרצה שאבצע מלא אוטונומית בלי תיבת מייל: נצטרך דרך אימות נגישה לבדיקה (למשל כתובת בדיקה שיש לנו אליה גישה).
4. רענון דף + פתיחה מחדש → המשתמש נשאר מחובר.
5. התנתקות → חזרה למצב לא מחובר וכפתור כניסה עובד שוב.
